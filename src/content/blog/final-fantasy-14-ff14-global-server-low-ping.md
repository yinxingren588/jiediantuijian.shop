## FF14 战斗系统快照 (Snapshot) 机制与 TCP 网络栈

《最终幻想 14》(Final Fantasy XIV) 虽然是一款基于 TCP 协议传输的 MMORPG，但在绝本（如绝欧米茄、绝伊甸）与零式高难副本中，它对网络延迟的要求丝毫不亚于第一人称射击游戏！

这源于游戏底层的**伤害判定快照 (Snapshot) 机制**：
- Boss 读条结束的瞬间，服务器会立即给当前场景拍下一张快照，只要快照时刻你在 AoE 范围内，即便随后你走出了金黄色的技能范围，伤害依然必中；
- 此外，高端职业循环普遍要求在 2.5 秒的 GCD 之间“双插能力技”。如果你的网络往返延迟超过 80ms，或者本地 Windows 开启了 **TCP Nagle 算法与 Delayed ACK**，能力技就会严重卡死公共 CD，导致原本能够打出的爆发循环彻底乱轴。

通过系统级关闭 TCP 延迟确认，并借助专线直达东京机房，可将延迟压制在 35ms 左右，实现丝滑无卡顿的行云流水双插连招。

## 生产级配置与工程落地指南

### Windows 注册表彻底关闭 TCP 延迟确认 (解除双插卡顿)

```text
# 步骤 1: 按 Win + R 输入 regedit 打开注册表编辑器
# 步骤 2: 定位到网卡配置路径：
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces

# 步骤 3: 在有具体 IP 地址的网卡子项右侧空白处，右键新建两个 DWORD (32位) 值：
# 1. 禁用 Nagle 算法 (立即发送数据包，不等待缓冲区填满)
TcpAckFrequency = 1
# 2. 禁用延迟确认 (收到包后立刻发送 ACK 回执)
TCPNoDelay = 1

# 步骤 4: 重启电脑使注册表 TCP 底层参数生效！
```

#### 推荐实施执行路线
1. 按照上述注册表指引为当前活动网卡配置 TcpAckFrequency 与 TCPNoDelay 参数并重启电脑
2. 在代理客户端中挑选针对日本东京机房有原生高速互联的专线节点
3. 使用开源的 XIVLauncher (第三方启动器) 启动国际服，享受官方补丁断点极速拉取
4. 在游戏木桩前测试三插或双插能力技，感受 GCD 转动是否如丝般顺滑

## 常见疑难故障排查与实战应对

### 场景 1：打高难副本时突然全员停滞奔跑原地踏步，十几秒后瞬间以 10 倍速快进倒地
- **底层成因分析**：本地网络与 SE 服务器之间的 TCP 连接被中间运营商重置或发生了剧烈的丢包阻塞。
- **针对性解决方案**：将 FF14 流量切换至具备多线热备的高质量专线节点，杜绝单点闪断。


### 场景 2：XIVLauncher 启动器更新游戏客户端时提示 'Patch files download failed (30413)'
- **底层成因分析**：SE 官方补丁分发 CDN 遭到了本地 DNS 污染，导致校验哈希失败。
- **针对性解决方案**：在分流规则中将 patch-dl.ffxiv.com 明确加入专线代理策略组。


### 场景 3：ACT 插件悬浮窗不显示 DPS 统计数据，战斗日志无法捕获
- **底层成因分析**：游戏开启了 DirectX 11 模式且本地代理软件的注入方式与 WinPCap 抓包驱动发生冲突。
- **针对性解决方案**：确保在 ACT 设置中使用 Memory (内存解析) 模式而非 Network (网络抓包) 模式进行统计。
