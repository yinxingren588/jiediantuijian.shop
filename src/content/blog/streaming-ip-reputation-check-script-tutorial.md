开源脚本并非简单地 ping 一下网页，而是完整模拟了各大流媒体客户端向授权服务器发起的底层鉴权握手：

## 在 Linux / Mac / WSL 终端一键运行流媒体体检脚本实操

### 生产级配置与实操代码

```bash
# 经典开源流媒体一键多平台全自动检测脚本命令
# 步骤一：通过本地代理运行开源检测探针 (需预先开启 Clash 本地 7890 端口)
export http_proxy="http://127.0.0.1:7890"

# 步骤二：拉取并执行知名开源流媒体检测脚本 (一行命令全自动完成)
```

#### 核心实施要点
1. **在终端中注入本地代理环境变量**：确保在运行脚本前执行 `export http_proxy=...`，让终端所有的探测请求全部通过你当前选中的代理节点发送。
2. **重点关注 Full Unlocked 标志**：挑选日常看剧节点时，认准脚本返回为绿色 `Yes (Full Unlocked)` 的节点，彻底告别半锁区烦恼。
3. **定期对节点进行体检抽查**：每隔两周运行一次脚本，及时掌握机场节点 IP 轮换后的最新解锁表现，挑出当下最丝滑的最佳节点。

## 运行检测脚本中的常见排错


### 场景 1：运行脚本提示‘curl: (7) Failed to connect to port 7890’
- **底层原因剖析**：本地代理客户端未启动，或者未开启‘允许局域网连接’导致终端无法连通代理端口。
- **针对性解决对策**：检查代理软件是否正常开启且处于可用状态。


### 场景 2：脚本显示全绿解锁，但自己在浏览器打开依然看不了
- **底层原因剖析**：本地浏览器缓存了之前的封锁状态 Cookie，或者本地浏览器开启了未受保护的 WebRTC 泄露。
- **针对性解决对策**：彻底清理浏览器关于该平台的 Cookie 数据，并安装 WebRTC 防泄露扩展后重新登录。
