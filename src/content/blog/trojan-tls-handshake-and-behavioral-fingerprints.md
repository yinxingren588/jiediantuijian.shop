## “特洛伊木马”的设计精髓：假作真时真亦假

如果一种加密流量看起来奇形怪状、与公网上的常见流量格格不入，哪怕它的加密强度高达 4096 位，审查系统的机器学习分类器也会直接将其标记为‘未知可疑流量’并施加限速或阻断。

针对这一对抗现实，**Trojan（特洛伊）** 协议应运而生。它的核心哲学完全摒弃了传统的‘自定义私有加密’，而是反其道而行之：**将自己完全融入世界互联网上最普遍、最合法的流量——标准 HTTPS 网页流量之中**。它是如何做到天衣无缝的？

## Trojan 协议的底层运作与 Nginx 回落防线

1. **标准 TLS 1.3 密码套件装扮**：Trojan 在数据传输前，执行与正常访问正规银行或电商网站完全相同的 TLS 1.3 握手流程，申请合法的 Let's Encrypt 证书，公网嗅探器只能看到标准的 HTTPS 数据流；

2. **握手密码身份校验**：在 TLS 隧道建立后，Trojan 客户端发送 56 个字符的预共享密码 SHA224 哈希值；

3. **优雅的 Nginx 假站回落机制 (Fallback)**：这是 Trojan 最令人称道的安全防线。如果审查系统发起主动探测或普通网民用浏览器访问该服务器的 443 端口，Trojan 服务端识别到密码错误，**绝不报错、绝不断开连接**，而是顺水推舟将其内部重定向至一个真实的 Nginx 静态博客或商业网站，完美欺骗探测！

## 生产级 Trojan 服务端 Nginx 回落配置与客户端实操

### 生产级配置与实操代码

```yaml
# Clash Verge Rev / Mihomo 客户端 Trojan 节点标准配置
proxies:
  - name: "🔒 伪装拟真-Trojan-香港"
    type: trojan
    server: hk-trojan.your-airport.com
    port: 443
    password: "YourStrongPasswordHere"
    sni: "hk-trojan.your-airport.com"
    skip-cert-verify: false # 严格核验真实合法 CA 证书
    udp: true
    client-fingerprint: chrome # 伪装 Chrome 真实指纹
```

#### 核心实施要点
1. **确保 skip-cert-verify 为 false**：关闭证书跳过检验，确保握手严格核验远程证书链的完整性，防止中间人伪造证书嗅探。
2. **客户端配置真实浏览器指纹**：在客户端中声明 `client-fingerprint: chrome`，保证 TLS 扩展与真实的谷歌浏览器保持 100% 字节一致。
3. **避免使用冷门非常规端口**：Trojan 只有部署在标准的 443 端口上才能发挥其完美的 HTTPS 混淆价值，若使用 38888 等高位端口反而会弄巧成拙。

## Trojan 协议常见排障排错


### 场景 1：提示‘certificate has expired’或证书无效
- **底层原因剖析**：机场运维人员忘记更新该节点域名的 Let's Encrypt 自动续签证书（证书有效期通常为 90 天）。
- **针对性解决对策**：向机场客服提交工单提醒证书过期，或临时勾选 `skip-cert-verify: true` 应急。


### 场景 2：直接用浏览器打开节点域名看到的是一个英文美食博客
- **底层原因剖析**：属于 Trojan 的正常安全回落机制，说明服务端的 Nginx 假站配置成功，并未发生故障。
- **针对性解决对策**：无需惊慌，在代理客户端正常导入配置连接即可出海。
