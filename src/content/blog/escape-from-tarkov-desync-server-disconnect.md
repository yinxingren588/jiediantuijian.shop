## 塔科夫网络模型与 150ms 强制踢出保护逻辑

《逃离塔科夫》(Escape from Tarkov) 是全球对网络环境最无情、挫败感最强烈的硬核射击游戏。

其底层网络堆栈具有两大冷酷特征：
1. **150ms Ping 限制硬红线**：为了防止高延迟外挂恶意卡延迟击杀，BSG 设置了极严格的高延迟踢出机制。只要你的网络往返延迟在短时间内**连续 5 秒超过 150ms**，系统不会给予任何容错，立刻弹出 **Server connection lost (与服务器连接断开)** 并将你强行踢出！在全装进图时，这一踢往往直接导致角色在原地变为活靶子，数百万卢布装备化为乌有。
2. **加载 Loot 阶段的大数据包冲击**：在进入对局的 "Loading loot 100%" 瞬间，服务器会在几百毫秒内向客户端灌入整个地图几千个物品的生成状态。如果本地网络 MTU 设置不当或存在缓冲丢包，该突发握手就会直接崩溃并报错断连。

## 生产级配置与工程落地指南

### 逃离塔科夫启动器与游戏对局分流规则

```yaml
# 针对 Escape from Tarkov 的防掉线专线策略
proxy-groups:
  - name: "Tarkov-Zero-Disconnect"
    type: select
    proxies:
      - "KR-IPLC-Tarkov-UltraLow-01"
      - "HK-IPLC-Tarkov-UltraLow-02"

rules:
  # BSG 启动器鉴权与跳蚤市场元数据
  - DOMAIN-SUFFIX,escapefromtarkov.com,Tarkov-Zero-Disconnect
  - DOMAIN-SUFFIX,battlestategames.com,Tarkov-Zero-Disconnect
  
  # 塔科夫核心对战数据 UDP 端口段 (大范围防止漏包)
  - DST-PORT,17000-17100,Tarkov-Zero-Disconnect,udp
  - DST-PORT,18000-18100,Tarkov-Zero-Disconnect,udp
```

#### 推荐实施执行路线
1. 在 Windows 网络适配器属性中，取消勾选 'Internet 协议版本 6 (TCP/IPv6)'，防止系统尝试走未优化的 IPv6 路由
2. 在 BSG 启动器中点击 'Change server'，手动勾选延迟低于 60ms 的香港、首尔与东京服务器，绝对不要勾选 'Use automatic server selection'
3. 选用支持原生 UDP 转发的 IPLC 游戏专线，并在客户端开启 TUN 模式
4. 大地图开局加载时，避免局域网其他设备开启视频流或下载任务，保证突发数据包 100% 顺畅解包

## 常见疑难故障排查与实战应对

### 场景 1：匹配到对局，在 'Awaiting session start' 卡了 3 分钟后弹出 Server connection lost
- **底层成因分析**：本地防火墙或路由器 NAT 阻断了服务器下发的入站 UDP 初始握手包。
- **针对性解决方案**：在路由器开启 Fullcone NAT 支持，或在 Windows 防火墙为 EscapeFromTarkov.exe 开放全部公网通信权限。


### 场景 2：进入街区 (Streets of Tarkov) 必定掉线，但打工厂 (Factory) 却非常稳定
- **底层成因分析**：街区实体与物品数量庞大，突发报文撑爆了本地 MTU，且由于内存不足导致网络进程挂起。
- **针对性解决方案**：将物理内存扩容至 32GB 以上，并在游戏设置中开启 '自动清理内存' 选项。


### 场景 3：被踢出后重新连接 (Reconnect)，每次刚进游戏 2 秒又被踢出来
- **底层成因分析**：当前专线节点发生路由震荡，实时延迟持续处于 155ms 以上触碰了踢出红线。
- **针对性解决方案**：立即在代理客户端切换备用低延迟香港专线，随后再次点击 Reconnect 返回战局。
